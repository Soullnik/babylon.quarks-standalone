The modules, in Shuriken's order

A system is the same stack as Unity's inspector: main settings, emission, shape, behaviors over life and by speed, forces, collision, sub-emitters, texture sheet, trails, renderer. The parity checklist lists what is shipped and what is not.

  1. One batched renderer per scene

    Systems that share a material are drawn together, so a screen full of muzzle flashes, hits and auras costs a handful of draw calls instead of one per system. The simulation runs on a column store with compiled behavior passes; on a CPU-only NullEngine, 100 000 particles over 16 emitters step in 9 ms where Babylon's built-in ParticleSystem takes 58 ms.

    Run the benchmark in your browser

  2. Trails, ribbons and beams

    RenderMode.Trail draws a ribbon through a particle's past positions, with WidthOverLength, texture modes (stretch, tile, repeat per segment), curve tension and world-space history. RenderMode.Beam is for lightning, tethers and lasers. Trails can be shed from the surface of a mesh through MeshSurfaceEmitter, and a teleporting emitter clears its history with clearTrails().

  3. 25 behaviors

    Each is a class you add to a system; curves are PiecewiseBezier, gradients are Gradient, and any of them can be random between two. Your own behaviors register through the plugin API and save in the same JSON.

  4. Texture effects inside the particle shader

    Flipbooks with frame blending, gradient maps, alpha erosion, UV distortion, soft particles, per-texture tiling, offset and scroll, and blend modes that treat alpha as coverage the way Unity's particle shaders do. Each one is off until you set it and compiles nothing when unused.

  • Mesh particles

    Any mesh as a particle, lit or unlit, with vertex colours, a rotation axis per particle and rim lighting; or emission from a mesh's surface with MeshSurfaceEmitter.

  • Sub-emitters

    EmitSubParticleSystem spawns a whole system when a particle is born or dies, or for every frame it lives, inheriting what you choose from the parent.

  • Pools and timelines

    EffectPool keeps copies of a one-shot effect ready so playing one allocates nothing. QuarksPrefab sequences systems on a timeline.

  • GLSL and WGSL, both hand-written

    Every shader has a WGSL twin, so WebGPU never loads a transpiler. CI compiles every variant of both languages on each change.

  • A documented JSON format

    Versioned JSON with a published schema. The same file round-trips through QuarksLoader, the editor and the Unity exporter; files from quarks.art load too.

Running in a few lines

Load an effect file from the editor or the Unity exporter, build a system in code, or embed the editor itself. 

import {BatchedRenderer, QuarksLoader, QuarksUtil} from 'babylon.quarks';

// One renderer per scene batches every system added to it.
const renderer = new BatchedRenderer('vfx', scene);

const effect = await new QuarksLoader(scene).load('effects/explosion.json');
QuarksUtil.addToBatchRenderer(effect, renderer);
QuarksUtil.play(effect);

scene.onBeforeRenderObservable.add(() => {
    renderer.update(scene.getEngine().getDeltaTime() / 1000);
});
import {Texture} from '@babylonjs/core/Materials/Textures/texture';
import {
    BatchedRenderer, Bezier, ConeEmitter, ConstantValue, IntervalValue,
    ParticleSystem, PiecewiseBezier, RenderMode, SizeOverLife,
} from 'babylon.quarks';

const renderer = new BatchedRenderer('vfx', scene);
const sparks = new ParticleSystem({
    scene,
    looping: true,
    startLife: new IntervalValue(0.6, 1.2),
    startSpeed: new IntervalValue(4, 8),
    startSize: new IntervalValue(0.05, 0.15),
    emissionOverTime: new ConstantValue(120),
    shape: new ConeEmitter({radius: 0.2, angle: 0.3}),
    renderMode: RenderMode.StretchedBillBoard,
    rendererEmitterSettings: {speedFactor: 0.05},
    texture: new Texture('spark.png', scene),
});
const shrink = new PiecewiseBezier([[new Bezier(1, 0.8, 0.4, 0), 0]]);
sparks.addBehavior(new SizeOverLife(shrink));
renderer.addSystem(sparks);
sparks.play();
import {Texture} from '@babylonjs/core/Materials/Textures/texture';
import {QuarksEffectEditor} from 'babylon.quarks-editor/react';

// The full editor (hierarchy, module inspector, timeline, undo) in any element.
const editor = QuarksEffectEditor.Show({
    hostElement: document.getElementById('editor')!,
    effectJson, // optional: an effect to open
    textureOptions: [{label: 'Glow', url: '/textures/glow.png'}],
    resolveTexture: (url, scene) => new Texture(url, scene),
    onSave: (json) => save(json), // round-trips through QuarksLoader
});

Export effects from Unity

Select a Particle System in Unity and choose Tools › Quarks › Export Selected Effect to JSON. Sub-emitters, grouped systems and textures come along; anything Shuriken has that babylon.quarks does not is reported by name. Unity 2020.3 and newer, installed as a .unitypackage, through UPM, or copied in.
